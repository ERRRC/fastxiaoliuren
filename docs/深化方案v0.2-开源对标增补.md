# 课程演示深化方案 v0.2 —— 开源项目对标增补

> 2026-09-05。基于 v0.1（四段式教学链）之上，对 6 个开源项目/成熟方案调研后的增补。
> 触发原因：v0.1 的断课体系仍偏骨架——"四步断课"有了结构，但每一步的**知识内容**不够厚。
> 调研对象：xiaoliuren_mcp、道传小六壬 skill、cyber-divination、jirukouya/xiaoliuren、HolmesZ/minor-ren、zlyup/liuren-divination-system。

---

## 一、调研结论总览：别人比我们厚的三层

| 层 | 我们现状 | 业界做法 | 借鉴来源 |
|---|---|---|---|
| **知识维度层** | 六宫 + 事类断语 + 日加时 30 组 | 多出 **六亲**、**体用**、**活/死六神**、十二长生 四个系统性维度 | 道传小六壬 skill |
| **规则覆盖层** | 30 组精确断语 + 少量格局，覆盖不全靠 fallback | **分层规则引擎**：精确组合 → 模式规则 → 通用推导 → 动态兜底，100% 覆盖 729 组合 | xiaoliuren_mcp |
| **输出结构层** | 结果页一段到底 | 排盘表（6 行属性）→ 分层解读 → 针对事类的三段式（现状/过程/结果）→ 建议，逐层折叠 | xiaoliuren_mcp + minor-ren |

关键认知：**成熟项目没有一家是靠"背 729 格断语"做深的**。xiaoliuren_mcp 号称覆盖 729 种组合，实际只有 19 条精确组合规则，其余靠 18 条五行模式规则 + 推导引擎生成。这正好适配我们的约束（纯前端、无法穷举人工撰写）——**深度来自"维度 × 规则"，不是来自"条目数量"**。

## 二、逐项目可借鉴点

### 2.1 aicoder2048/xiaoliuren_mcp ⭐ 最值得抄架构

- **分层规则引擎**（优先级从高到低）：
  1. 精确组合匹配（19 条，相当于我们的 combos.json pairs 30 组）
  2. 五行流转模式匹配（18 条，如"三传连生""二克一"）
  3. 阴阳平衡模式（4 条）
  4. 动态规则生成（通用推导兜底）
- **四维分析**：五行流转 / 吉凶组合 / 阴阳平衡 / 发展趋势
- **输出模板**：起卦方式 → 排盘表 → 三传 → 四维分析 → 综合评分 → **针对问题的三段式解读（当前情况 / 发展过程 / 最终结果）** → 建议
- ⚠️ 它的"动态引擎"部分依赖 LLM（MCP 架构），我们是纯 JS，只能抄它的**分层结构和规则内容**，推导引擎要自己写确定性规则。
- ⚠️ 它有"综合评分 X/100"——见第六节宪法审查，**不建议照抄**。

### 2.2 tianmingwangluo/xiaoliuren-skill（道传小六壬）⭐ 最值得抄知识

SKILL.md 单文件约 700 行，知识密度高，全部可结构化：

- **排盘表 6 行**：宫位 / 五行 / **六亲** / 死六神 / 活六神 / 时辰。比我们多两个可计算维度（六亲、活六神）。
- **六亲体系**（以时宫五行为"我"，对月宫/日宫判定）：
  | 关系 | 判定 | 象意 |
  |---|---|---|
  | 兄弟 | 同五行 | 同辈，竞争或合作 |
  | 父母 | 他生我 | 庇护，长辈，文书 |
  | 子孙 | 我生他 | 晚辈，产出，福德 |
  | 妻财 | 我克他 | 财富，收获 |
  | 官鬼 | 他克我 | 压力，疾病，官府 |
  → **5 条规则覆盖全部 6×6 生克关系，纯计算，零人工断语成本**。
- **体用关系**：人宫（时宫）为体，起课的时辰地支五行为用，看生克。又是纯计算。
- **六步解卦法**（方法论，可直接当结果页的信息架构）：
  1. 初判吉凶（时宫吉凶 + 体用生克）→ 2. 明确定位（事类）→ 3. 细析三宫（五行生克、气势流向）→ 4. 活用类象（单宫/合宫象征）→ 5. 运用技法（六亲、体用）→ 6. 综合判断（结论 + 行动指导）
- **每宫 7 类分类断语**（疾病/婚姻/行人/事业/财运/寻物/官司 + 象意 + 传统口诀）——见第三节，直接解决我们的 topics 覆盖欠账。
- ⚠️ **流派警报**：道传声称"留连属**土**、小吉属**水**"才是对的，网上常见版本"留连水"是错的。**我们的 palaces.js 用的是留连水、小吉水**。见第七节，必须用户拍板。
- ⚠️ 死六神/活六神是道传特色体系（活六神按时辰起青龙，口诀"子午大安丑未留…"）。我们的六神是静态的（大安青龙、留连玄武、小吉六合…），两套不一致，也是流派决策。
- ✅ 工程做法值得学：`examples.md` 7 组标准验证用例（含 0、6 的倍数等边界）——我们的 test.js 只有 3 个报数锚点，可扩充。

### 2.3 fysh1010/cyber-divination

- 六神速查表结构化（六神/吉凶/五行/方位/主要含义），可直接对照我们的 palaces.js 补字段（我们缺"方位"）。
- 占卜原则文案："遇事即刻起卦，无事勿占；凡事只占一次，再占不验；同一事件只能用一种时间起卦"——**这几条很适合放进起课页的教学提示**，也是流派通行的礼法，能强化"占卜工具"定位。
- 推荐书目清单（《小六壬秘籍》《掐指神算》）——学习 Tab 可加"延伸阅读"。

### 2.4 jirukouya/xiaoliuren

- 双体系：主流三传 + **秘传三传（九格法）**。九格法是加分项，暂不纳入（先做好通行体系）。
- **真太阳时校正**（按经度 + 天文均时差 EoT 修正时辰）——对我们是可选增强。12:00 整起课在真太阳时下可能已过午时正中，严格流派讲究这个。纯 JS 可算（只需经度，可让用户手填或用默认东经 120°）。P2 优先级。

### 2.5 HolmesZ/minor-ren（UI 模式）

- 展示三层：三字结果 → 五行要点 → 六星断词，**断词详解默认折叠**。
- 与我们 v2.0 已做的"简略模式"同思路，验证了方向正确。可再借一点：**结果页默认只展开"与所选事类相关"的段落，其余全部折叠**——信息密度高但不淹没。

### 2.6 zlyup/liuren-divination-system

- 教学中心结构：完整教程 / 六宫详解 / 文化背景 / 天气谚语。我们是题库驱动的教学，结构不同，仅借鉴"文化背景"栏目可加进学习 Tab（P2）。

## 三、P0 增补：事类断语一次补齐到 6/6

v0.1 把"补 topics"列为前置欠账，当时以为要自己考证。调研发现**道传 skill 每宫自带 7 类分类断语**（疾病/婚姻/行人/事业/财运/寻物/官司），加上我们已有的（失物/行人/官事/疾病/求财/婚姻/宅舍/交易/出行/求谋），合并去重后每宫可到 **10 类左右**。做法：

1. 以道传 7 类为骨架对照 `palaces.js` 现有条目，逐条标注来源（`道传小六壬` / `palaces.js 原有` / `通行口诀`）；
2. 口诀本身（如大安"求财在坤方，失物去不远，宅舍保安康，行人身未动，病者主无妨"）就是我们 palaces.js 断语的同源，**溯源链天然成立**；
3. 冲突条目（如同宫断语两派不同）标注流派并展示通行说法，宪法 v2 允许这种"教学性展示"。
4. 每宫补"方位"字段（大安东/速喜南/赤口西/小吉西南…），为断语"往哪个方向找"类内容服务。

预计工作量：一次结构化整理，约 6 宫 × 10 类 × 平均 30 字 ≈ 每宫 300 字，加来源标注。

## 四、P0 增补：两个纯计算新维度（六亲 + 体用）

这两个维度是"深度感"的最大来源，且**完全不需要人工断语**——5 条六亲规则 + 8 条生克关系就能对任意课式输出一段有内容的解读。四步断课升级为：

```
① 三才定位（已有：起因/过程/结局）
② 日加时组合断语（已有：30 组 + 同宫降级）
③ 五行分析（升级）：
   a. 三宫两两生克（月×日、日×时、月×时）→ "气势流向"
   b. 六亲：以时宫为"我"，月宫/日宫的六亲
   c. 体用：时宫五行 vs 起课时辰地支五行
④ 格局判定（已有：先吉后凶/虎头蛇尾等，可增"三传连生""二克一"两条五行模式，借鉴 xiaoliuren_mcp）
```

**来源标注策略**：六亲/体用的判定规则是五行常法机械推导（a 生 b = 父母…），结果文本模板化生成，统一标注"编者按五行常法推导，非古法原文"——符合宪法 v2。

**示例**（课式：月=大安木 / 日=留连水 / 时=小吉水，问求财）：
- 三才：起因吉（大安），过程滞（留连），结果吉（小吉）
- 生克流向：月木 → 生？无；日水 → 生月木（水生木）；时水与日水比和
- 六亲（以时宫水为我）：月宫木 → 我生他 = **子孙**（产出、福德）；日宫水 → 兄弟（同辈，竞争或合作）
- 体用：若起课时辰为午（火），水克火 = 我克他 = 妻财 → "体克用，财可得但需主动争取"
- 合成一句："起头不错、中段反复耗磨、最终能成；求财方向上你需自己出力（体克用），时机上水生木助力来自外部环境。"

这段话的信息密度已经超过"留连=凶"级别的浅断。**全部由规则生成，无一行人工逐格断语。**

## 五、P1 增补：分层规则引擎 + 结果页信息架构

### 5.1 规则引擎四层（照抄 xiaoliuren_mcp 结构，纯 JS 实现）

```
L1 精确匹配：combos.json pairs 30 组 + patterns 5 格局   → 标注"通行本原文"
L2 模式规则：五行流向模式（三传连生/二生一克/比和…约 8 条，新写）
            + 格局规则（先吉后凶等，已有）
                                                          → 标注"通行说法整理"
L3 系统推导：六亲 + 体用 + 三宫生克（第四节，全覆盖）      → 标注"编者按五行常法推导"
L4 兜底：单宫事类断语（补齐后 10 类/宫）+ 总象文案        → 标注"通行断语"
```

任何课式保证有 L3/L4 输出；命中 L1/L2 时叠加展示。**每条输出带来源徽标**，UI 上用不同底色小标签区分（原文=金边、整理=蓝边、推导=灰边），诚实原则的 UI 化。

### 5.2 结果页信息架构（对照 xiaoliuren_mcp 模板 + minor-ren 折叠）

```
课式卡（始终展开）：三宫大字 + 事类 + 起课时间
├─ 断语速览（始终展开）：所选事类的 L4 断语 + 来源徽标
├─ 三才与格局（默认展开）：L1/L2 命中项
├─ 五行深析（默认折叠）：生克流向 / 六亲 / 体用
├─ 其他事类参考（默认折叠）：同一课式下其他事类的断语（教学用："同课不同问"）
└─ 免责与高危提示（固定，高危事类不可关闭）
```

"其他事类参考"是个低成本高价值点：课式只算一次，换个事类 tab 只是换断语，还能顺势教学"小六壬问法不同、断语不同，课面相同"——反过来强化诚实原则。

## 六、明确不抄的部分（宪法审查）

| 业界做法 | 结论 | 理由 |
|---|---|---|
| 综合评分 X/100（xiaoliuren_mcp） | **不做** | 数字化吉凶 = 变相确定性预测，且百分比给人伪精确感。替代：三宫吉凶构成可视化（2 吉 1 凶这种**纯统计事实**） |
| "针对问题的建议"板块 | **降级** | 建议改为"通行断语 + 行动提示"（如大安出行断"宜缓行"），不给现代生活决策建议 |
| 一键随机起课（minor-ren 等） | **不做** | 与"一事一占、心念动而取数"的礼法相悖，也助长刷课 |
| LLM 生成解读 | **不做** | 违反铁律 2（无后端无依赖），且来源不可溯源 |

## 七、必须拍板的流派决策（影响已上线代码）

调研暴露了一个**现在就有影响**的问题：

| # | 议题 | 我们现状 | 道传主张 | 影响 |
|---|---|---|---|---|
| 1 | **留连五行** | 水（玄武） | **土** | 直接改变 L3 所有生克/六亲推导结果；留连出现率约 1/6 课 |
| 2 | 小吉五行 | 水（六合） | 水（一致✓） | 无冲突 |
| 3 | 六神体系 | 静态六神（大安青龙/留连玄武/小吉六合/空亡勾陈） | 死六神（小吉=玄武）+ 活六神（按时辰起青龙，腾蛇/四方土入场） | 是否引入活六神决定排盘表多一行、教学多一章 |
| 4 | 体用维度 | 无 | 人宫为体、时辰为用 | 纯新增，不冲突，建议直接加 |

说明：留连五行两派都有文献（通行网络版本多作水，部分秘传本作土）；**我们 test.js 锚点和题库 269 题都是按"留连水"写的**，改五行 = 改题库部分题目解析 + 引擎注释，动静不小。我的建议：**维持留连水不动，在速查卡加一条"流派差异说明"**（各家五行归属有异，本作依通行网络版本），把道传版本作为教学对照——除非你实际学的是道传体系，那必须改。
