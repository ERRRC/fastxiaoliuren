## 一、这是什么项目

**掐指小六壬**（appId `com.qiazhi.xiaoliuren`）：免费、无广告、**完全离线**（无后端、无账号、不联网）的纯 Web 应用 + Android APK。内容是传统小六壬（诸葛马前课）的起课与断语，附完整教学和 269 题题库。

**产品定位有过一次大转弯（2026-09-04，v2.0 起）**：

- **v1.x 教学工具**：宪法是「教你算，不替你算」——只教方法、判对错、存记录，禁止输出吉凶；起课引擎藏在判卷器里，不直接面向用户出卦。
- **v2.x 占卜工具**：用户选事类 → 起课 → 直接给该事类在这一课上的通行断语；教学降为「学习」Tab。
  宪法 v2 的核心约束（改动必须遵守，详见 `docs/产品宪法v2与占卜化改造方案-v0.1.md`）：
  1. 断语必须可溯源、不得杜撰（单宫断语查 `palaces.json`，组合断查 `combos.json`，推导内容必须标注"编者按五行常法推导"）；
  2. 禁止确定性预测与决策建议，禁止今日运势类无课式内容；
  3. 高危事类（疾病/投资/法律）结果页强制提示，不可关闭；
  4. 全站固定免责声明：属民俗文化内容，不构成对任何具体事项的预测或决策建议；
  5. 诚实原则：课式只由起课时间（或报数）决定，**所问之事不参与任何计算**，界面不得暗示"系统理解了你的问题"。
- 完全免费，无内购、无广告。

⚠️ 历史决策说明：产品方案 v1.0 锁定过"纯 Web/PWA，不上应用商店"。2026-08-31 增加 Android APK 打包（Capacitor 壳），只做**侧载分发**（GitHub Releases），不上架商店。若要上架商店或商业化，需先与作者确认（占卜类在国内安卓市场属敏感品类）。

## 三、Web 应用架构（10 分钟看懂）

加载顺序（index.html 底部，带 `?v=2` 缓存参数）：`solarlunar → engine.js → palaces.js → questions.js → app.js`。无打包器、无框架、无 ES module，纯 IIFE + 全局变量。

**数据流**：`palaces.json`（权威数据）⇄ `palaces.js`（运行时形态，两者内容须一致）；`questions/_c*.json` → `build.js` 校验合并 → `questions.json` → 包一层 UMD → `questions.js`（暴露 `window.QUESTIONS`）。

**引擎 API**（engine.js，`XLR` 命名空间）：

```js
XLR.computePalaces(lunarMonth, lunarDay, shichenIdx) // → {monthPalace, dayPalace, hourPalace}，0-5 对应六宫
XLR.shichenIndex(hour)    // 0-23 小时 → 时辰序 0-11（子=0；23点与0点同为子时）
XLR.solar2lunar(y, m, d)  // 公历 → 农历（闰月按本月数处理）
```

起课规则：月宫=(月−1)%6；日宫=(月宫+日−1)%6；时宫=(日宫+时辰序)%6。六宫顺序固定为：大安→留连→速喜→赤口→小吉→空亡（对应食指根→食指尖→中指尖→无名指尖→无名指根→中指根）。

**用户数据**：只存 `localStorage`，键 `xlr_bank`（错题/练习记录 JSON）。没有后端、没有账号体系。

**掌图坐标**：app.js 顶部 `NODE_POS` 数组是六宫在掌图上的像素坐标（图片 1024×1536，SVG viewBox 从 100,40 起裁剪）。换底图必须重标这 6 个点。**⚠️ 左右手事故（2026-08-31）**：初版底图是"观者视角"（拇指在右），解剖学上实为右手掌——用户以实拍左手照片纠错。现图已水平镜像为**第一人称视角（掌心对着使用者，拇指在画面左侧）**，NODE_POS 的 x 坐标同步取镜像（x→1024−x）。**今后换底图必须保持拇指在左**，否则学员举起自己左手会对不上。原始未镜像图保留在 `assets-src/palm.png`（勿直接使用）。

**验证手段**：改完引擎/数据先跑 `node test.js`（17 个历法与起课锚点，必须全绿）。

## 四、题库工作流（当前 143 题）

现状：六宫基础 34 / 宫位属性 27 / 断语口诀 52 / 情景判断 30。章节编号 c1/c2/c3/c5（c4 未开）。

加题/改题流程：

1. 按输入到 `questions\_c1.json`（或对应章节文件），格式规范见 `题库接口说明.md`（id 格式 `c1-0001`、source 必须是「诸葛马前课通行本」、judge 题 options 必须是 ["正确","错误"] 等，build.js 会逐条校验）。
2. `node questions/build.js` → 校验通过会重写 `questions.json`；有错会列出并拒绝写盘。
3. 把 questions.json 编译成 questions.js（UMD 包壳，项目里暂无专门脚本，可直接用）：

   ```bash
   cd 仓库根目录
   node -e "const fs=require('fs');const q=fs.readFileSync('questions/questions.json','utf8').trim();fs.writeFileSync('questions.js',\"(function(root,f){if(typeof module!=='undefined'&&module.exports){module.exports=f();}else{root.QUESTIONS=f();}})(typeof self!=='undefined'?self:this,function(){return \"+q+\";});\")"
   ```

4. 同步并重新打包 APK（见下节）。

⚠️ 如果要新增题目类型或字段，先改 build.js 的校验逻辑和 `题库接口说明.md`，保持三者一致。

## 五、Android 打包

> **本节只留结论，完整流程（环境准备、签名、发版、CI、常见坑）见 `docs/BUILD.md`。**

技术栈：**Capacitor 6**（不是 7/8 —— 见第六节）。appId `com.qiazhi.xiaoliuren`，应用名「掐指小六壬」，versionCode/versionName 在 `android/app/build.gradle`（当前 versionCode 13 / versionName 2.1）。

**日常重打包（改了任何网页文件之后）：**

```bash
cd <仓库根目录>
node build-apk.js release          # = sync-www.js + cap sync android + gradle assembleRelease + 拷到 dist/
# 等价手动版：
#   npm run sync && cd android && ./gradlew assembleRelease   （Windows 用 gradlew.bat）
```

**改完代码要改版本号**：`android/app/build.gradle` 里 versionCode +1（否则覆盖安装不生效）。

**签名（重要）**：

- 发布签名文件 `android/keystore.jks`（别名 `qiazhi`，有效期至 2056 年）与密码文件 `android/keystore.properties` **只存在作者本机，不进仓库**（仓库是公开的）。
- **此文件丢失或更换后，老用户无法覆盖安装，只能卸载重装（会丢本地课例与练习记录）。** 请提醒作者多处备份。
- 构建时 `android/app/build.gradle` 按 keystore.properties → 环境变量 → debug 签名 的顺序取签名配置；别人 clone 后没有 keystore 也能构建（debug 签名，仅自测）。

**图标**：`make-icons.js`（sharp）生成全套 mipmap + 自适应图标；自适应背景色在 `android/app/src/main/res/values/ic_launcher_background.xml`。想换图标改这个脚本重跑即可。

**真机调试**：adb 一般在 `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`。手机开 USB 调试连上后 `adb install -r <apk>` 即可。

## 六、本机构建环境的坑（换机器/重装系统前必读）

1. **Java 版本陷阱**：Gradle 8.2.1 / AGP 8.2.1 跑不了 Java 21+，必须用 **JDK 17**。作者本机 JAVA_HOME 指向 JDK 21，所以在**用户级**配置 `~/.gradle/gradle.properties` 里钉死了 `org.gradle.java.home=<JDK17 路径>`（刻意不写进仓库的 `android/gradle.properties`，否则别人 clone 后必挂）。换机器要重新钉一次，见 `docs/BUILD.md`「环境准备」。
2. **Gradle 发行版**：`android/gradle/wrapper/gradle-wrapper.properties` 已从模板默认的 `-all.zip` 改成 `-bin.zip`（原 `-all` 缓存损坏，会卡在 200MB 下载上，已删）。若见卡在 "Downloading gradle-8.2.1-bin.zip"，可等它下完（新机器首次构建正常现象）或用本地缓存直接构建（命令见下条）。
3. **离线直接构建**（绕过 wrapper 下载）：

   ```bash
   GD="$USERPROFILE/.gradle/wrapper/dists/gradle-8.2.1-bin/q1aamv6tqvtnrpk8h170iobo/gradle-8.2.1/bin/gradle.bat"
   cd <仓库根目录>/android && cmd //c "$(cygpath -w "$GD")" assembleRelease --console=plain
   ```

4. **为何是 Capacitor 6**：Capacitor 7+ 要求 JDK 21 + compileSdk 35（本机无 35 平台），6 与本机 Java 17 + SDK 34 + Gradle 8.2.1 + AGP 8.2.1（全有缓存）完全匹配。想升级 Capacitor 必须连带着升 JDK，别只升其一。
5. Android SDK：**在 `D:\Android_Sdk`**（platforms 34/36/36.1，build-tools 34/35/36，licenses 已接受；Android Studio 装在 `E:\androidstudio`）。
   ⚠️ 2026-09 实测 `%LOCALAPPDATA%\Android\Sdk` 已不存在（`ANDROID_HOME` 环境变量仍指向旧路径，已失效）。真正生效的是 `android/local.properties` 里的 `sdk.dir`（该文件不进仓库）。
   写这个路径用正斜杠最省事：`sdk.dir=D:/Android_Sdk`。若要用反斜杠，必须按 Java properties 转义写成 `sdk.dir=D\:\\Android_Sdk`；少写一个反斜杠会得到非法路径，构建报「文件名、目录名或卷标语法不正确」（2026-09-14 实测踩过）。
6. Shell 是 Git Bash：调 .bat 用 `cmd //c`，Windows 路径用 `cygpath -w` 转换。**注意：`cmd //c "gradlew.bat ..."` 在本机实际不会执行目标命令**（只弹一个空 cmd），验证构建请直接调本地 gradle 二进制：
   `MSYS_NO_PATHCONV=1 "$USERPROFILE/.gradle/wrapper/dists/gradle-8.2.1-bin/q1aamv6tqvtnrpk8h170iobo/gradle-8.2.1/bin/gradle" assembleRelease --console=plain`
7. **删除拦截陷阱（v1.1 实测踩坑）**：本机所有 `fs.rmSync`/`rm` 会被外层安全层接管，走回收站且"实际删了却回报失败"。后果是 `npx cap sync android` 的 update 步骤会**反复删 `capacitor-cordova-android-plugins/` 目录并报错退出**，整个目录会被删光。恢复办法（v1.1 已做过一次，模板都在 node_modules 里）：
   - 解 `node_modules/@capacitor/cli/assets/capacitor-cordova-android-plugins.tar.gz` 到 `android/capacitor-cordova-android-plugins/`（注意 tarball 内部是**平铺路径**，先解到临时目录再拷，别直接 `-C android/`，会覆盖根 build.gradle）；
   - `cordova.variables.gradle` 由 update.js 生成，模板在 `node_modules/@capacitor/cli/dist/android/update.js` 227 行附近（capacitor 6 固定写死 minVersion 22），可直接手写；
   - 插件 build.gradle 的 `PLUGIN GRADLE EXTENSIONS START/END` 之间必须有一行 `apply from: "cordova.variables.gradle"`。
   - **在本机不要跑 `npx cap sync android`**。等价替代：`node sync-www.js`（已加先删后拷逻辑）+ 手动 `cp -r www/* android/app/src/main/assets/public/`（capacitor 会补 cordova.js 等空文件，已存在则无需再跑）。
8. sync-www.js 已改为"先删后拷"：换资源名（如 palm.png → palm.webp）时旧文件不会静默留在包里。删除失败会被忽略，靠覆盖兜底。

## 八、协作守则（给 AI）

1. 改任何行为前先读宪法：**v2.0 起以 `docs/产品宪法v2与占卜化改造方案-v0.1.md` 为准**（旧宪法在教学版方案 `docs/产品方案-v1.0.md` 里，已部分被取代）；与宪法冲突的需求要向作者提出而不是照做。
2. 内容类改动（口诀、类象、断语）必须能在 `palaces.json` 中找到出处；找不到就别写进题目或解析。
3. 动了 engine.js 或 palaces 数据 → 必跑 `node test.js`。
4. 动了网页文件 → 走 `docs/BUILD.md` 的同步 + 打包流程（`node build-apk.js release`），APK 里的代码才会更新（**APK 不会热更新**，改完必须重新出包并升 versionCode）。
5. `www/`、`questions/questions.json`、`questions.js` 是生成物，改源头不改生成物。
6. 不引入框架/构建器/后端——这个项目刻意保持"双击 index.html 就能跑"的形态。
