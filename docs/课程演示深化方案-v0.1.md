# 课程演示深化方案 v0.1

针对「演示太浅，只看落宫」｜2026-09-04

---

## 一、诊断：到底浅在哪

课程演示现在的信息链条是这样的（`app.js`）：

```
起课参数（月/日/时）
   ↓ 三步掐算动画
月宫 · 日宫 · 落宫（三个 chip）
   ↓ renderResult()
结果卡：只渲染 P[res.hourPalace] —— 落宫一宫的断语
```

**问题 1｜掐了三步，丢了两步。**
演示完整算出月宫、日宫、时宫，但结果卡只取 `res.hourPalace`。掐算过程教了"怎么起课"，结果却只讲"落宫是什么"——等于花了三步的力气，只用了三分之一的信息。三宫在课里分别是**起因 / 过程 / 结局**（`combos.json` 三才定位），这才是"一课"，落宫只是末传。

**问题 2｜演示教到 L1，题库考到 L3，中间是断的。**
题库 L3（组合课断 40 题 + 辨析进阶 22 题）在考：三才合论、日加时 30 组、五种格局、五行生克。但演示页从头到尾没教过这些。用户刷完演示直接进 L3，会明显断层——**演示是入口，却没把人送进去**。

**问题 3｜"落宫"这个词本身在误导。**
落宫 = 时宫 = 末传，是结局、是定论点，但不是全部。只讲落宫，用户会形成"小六壬 = 算出落宫查断语"的错误心智模型，这正是"浅"的根源。

**问题 4｜没有"怎么断"的示范，只有"结果是什么"。**
演示展示的是**查表**（落宫→断语），不是**推理**。真正要教的是：拿到一课，按什么顺序看、每层看什么、怎么把三层合成一句话。

---

## 二、目标：深化后，一次演示要教到什么程度

用户看完一次演示，应该能回答：

1. 这一课的三宫是哪三宫，各自代表什么（起因/过程/结局）
2. 落宫为什么是"定论"但不能"独断"
3. 日宫 + 时宫这对组合，通行本日加时诀怎么说
4. 这一课入不入某一种格局（先忧后喜 / 虎头蛇尾 / 先吉后凶 / 苦尽甘来）
5. 三宫五行之间谁生谁克，助力在哪、阻力在哪
6. 问具体事类（求财/失物/行人…）时，该看哪一句

**验收标准**：一个 L1 用户看完 2 次演示，去做「组合课断」章节的题，不应该觉得"这考的东西我没见过"。

## 三、方案总览：把演示从"一段"改成"四段"

```
① 起课   三步掐算（现有，加"简略模式"）
             ↓
② 课式   三宫并列：月宫(起因) · 日宫(过程) · 时宫(结局)  ← 【A 模块】
             ↓
③ 断课   四步推演：三才 → 日加时 → 格局 → 五行生克      ← 【B 模块，灵魂】
             ↓
④ 精断   按事类定位断语 + 断语定位练习 / 课例库        ← 【C 模块】
```

### 模块 A｜三宫课式（必修，直接解药）

**做什么**
- 结果卡从"落宫 XX"改为**三宫课式条**：三宫并排，每宫显示 宫名 + 五行 + 六神 + 吉凶 + 三才角色（起因/过程/结局）。
- 落宫仍标为「定论」，但加一句提示（用 `combos.sancai` 原文）：
  > 观课以时宫为定论，但不可只看时宫孤立下断。
- 月宫、日宫在演示过程中落定时，chip 上直接带上三才角色，不再只写宫名。

**数据依赖**：`palaces.js`（已有）+ `combos.json.sancai`（3 条，已有）

**改哪里**：`renderResult()`（app.js:144）、`setChip()`（app.js:228）、结果卡 HTML 模板

**工程量**：小

---

### 模块 B｜四步断课推演（必修，本方案的灵魂）

演示结束后新增**「断课演示」折叠卡**，按固定四步展开，每步都标注出处：

| 步骤 | 内容 | 数据源 | 出处标注 |
|---|---|---|---|
| 1. 看三才 | 月=起因、日=过程、时=结局，各宫一句话 | `combos.sancai` | 三才合论·通行教法 |
| 2. 看日加时 | 查 (日宫, 时宫) 那一条，出 verse + 白话 + gist | `combos.pairs`（30 条） | 日加时诀·通行本（三源印证） |
| 3. 看格局 | 比对 5 种格局，命中则显示；不命中显示"不入特定格局，按常法断" | `combos.patterns`（5 条） | 易卦网三才合论课例 |
| 4. 看五行生克 | 月→日、日→时、月→时 三条关系，各判 生/克/比和 | `palaces.js.wuxing` + 生克规则 | **须标"编者按五行常法推导"** |

**关于第 4 步的重要说明**：
`combos.patterns` 里"三宫生克"只有一条示例，没有 27 组细则。系统化的生克判断是我们**按五行常法推导**出来的，不是古法原文。必须显式标注为"编者推导"，不能伪装成文献——这跟项目一贯的溯源纪律一致。

**数据依赖**：`combos.json`（**目前不在 www 里，见第五节**）

**改哪里**：新增 `interpret(res)` 模块 + 结果卡新增折叠区

**工程量**：中偏大

---

### 模块 C｜落宫精断（强烈建议，但要分两步）

**C-1 断语定位练习（交互，教学性强）**
给出事类（如"丢了手机"），问用户"该看哪一宫的哪一句？"，四个选项，选完给解析 + 溯源。
- 这解决了「演示是看、不是练」的问题
- 完全不触碰产品宪法——不给用户算，只教用户怎么查

**C-2 课例库（教材例题）**
内置 12–20 个有代表性的三宫组合（如 大安·留连·速喜 = 先忧后喜），每个配中性情景 + 完整断课链，可翻阅。
- 课例是编的教材例题，跟"替你算"无关
- 直接补上 L3 缺的"完整课例走一遍"

**数据依赖**：`palaces.js.topics` —— **当前覆盖极不均匀，见第五节欠账 2**

**工程量**：大（主要在补数据，不是写 UI）

---

### 模块 D｜应期（后置，不要混进本轮）

口诀里的应数断语（如"谋事主一五七"）目前 `palaces.js` 根本没有这个字段，想教没有源头。属数据层欠账，建议独立一轮做：先考证补字段，再做教学。**本轮不碰。**

## 四、交互与布局改造（不做的话会翻车）

演示页内容量会翻 3–4 倍，手机端（掌图已占 56vh）必须同步改：

1. **分阶段展开，不要一次堆完**：起课动画 → 课式卡 → 断课卡（默认折叠，点开才展开）。
2. **新增"简略模式"开关**：熟练用户跳过逐格数步，直接跳到三个落点。农历七月十九要数 7+19+8 = 34 步，重温时是折磨。
3. **断课卡用折叠 + 步骤编号**，每步可单独展开收起，避免长滚动。
4. 结果卡顶部**固定一行教学提示**："本页只演示断法，不构成对任何具体事情的预测。"

## 五、数据层欠账（必须先补，否则方案落不了地）

做完调研发现 3 个硬缺口，都是**数据问题不是代码问题**：

**欠账 1｜`combos.json` 前端拿不到**
`www/` 下只有 app.js / engine.js / palaces.js / questions.js，**没有 combos.js**。`combos.json` 目前只在 `questions/` 目录里给 build.js 校验用。模块 B 要跑，必须先把它搬进 www（新增 `www/combos.js`，由构建脚本从 `questions/combos.json` 生成，保持单一源头）。

**欠账 2｜日加时缺"同宫"组合（6 组）**
`combos.pairs` 现有 30 条，覆盖 6×5 异宫组合，**没有 大安+大安、留连+留连 这类同宫**。
同宫概率不低：时宫 = (日宫 + 时辰序) mod 6，时辰序 0–11 模 6 后各两次 → **时宫 = 日宫 的概率约 1/6**。深化演示后必然撞上，不补就是空白。
建议：先上降级文案并显式标注——
> 日时同宫，课体纯一，吉凶之力加倍，以该宫本义断之。（本体系补注，非通行本原文）

后续若考证到通行说法再替换。

**欠账 3｜`palaces.js.topics` 事类覆盖极不均匀**

| 事类 | 覆盖宫数 | | 事类 | 覆盖宫数 |
|---|---|---|---|---|
| 失物 | 6/6 ✅ | | 求财 | 3/6 |
| 行人 | 6/6 ✅ | | 官事 | 3/6 |
| 疾病 | 4/6 | | 交易 | 1/6 |
| 口舌 | 2/6 | | 出行 | 1/6 |
| 宅舍 | 1/6 | | 求谋 | 1/6 |

只有失物、行人全覆盖。做模块 C 的"按事类精断"，选了"出行"只有速喜有答案。补到 6/6 全覆盖是 C 的前置条件，且每一条都要能溯源。

## 六、产品宪法自检

项目铁律第 1 条：**「教你算，不替你算」**——禁止"输入问题→输出吉凶"。

模块 B 有擦边风险：用户把参数拨到自己的事发时间，会把"断课演示"当占卜结果用。缓解措施（三条同时上）：

1. 演示的输入是**农历月日时**（可随便拨的数字），不是"你的问题"——输入形态上就不是占卜。
2. 断课卡措辞用"按通行本法，这一课的**教学解读**是……"，不用"你的结果"。
3. 结果卡顶部固定教学提示 + 断课卡默认折叠，需要主动点开。

**这三条形同虚设还是足够，需要你拍板**（见第八节决策点 1）。

## 八、需要你拍板的 4 个决策点

**1｜断课卡要不要上？（宪法边界）**
- 上，配三条缓解措施（我的建议）
- 上，但只放到「速查卡」Tab，演示页保持克制
- 不上，只做模块 A（三宫并列）

**2｜五行生克怎么处理？**
- 按规则推导 + 显式标注"编者推导"（建议，快）
- 先考证到文献再上（慢，可能考不到）
- 不做这一步，断课只走三步

**3｜日时同宫的 6 组，补不补？**
- 先上降级文案（本体系补注）（建议）
- 先考证通行说法（慢）
- 撞到同宫时直接不显示这一步

**4｜批次怎么排？**
- 按 v2.0 → v2.3 顺序做（建议）
- 只做 v2.0，先看看效果
- v2.0 + v2.1 合并一次做完
